Temperature Ranking API
=======================

Endpoint
--------

GET /api/temperature

Use this endpoint from a bot or external service to get today's forecast maximum
temperature for a city, plus the accuracy of the best single forecast model and
the best averaged model combination.

This endpoint is private. Requests must include your secret API key.

API_SECRET


Query Parameters
----------------

city
  City name, city id, or METAR station code.
  Examples: London, london, New York, KLGA, Beijing, ZBAA

station
  Alternative to city. Use a METAR station code.
  Examples: EGLC, KLGA, KDAL

unit
  Optional. C or F.
  If omitted, the API uses the city's default unit.


Examples
--------

Local development:

  curl -H "X-API-Key: YOUR_SECRET_VALUE" "http://localhost:3000/api/temperature?city=London&unit=C"
  curl -H "X-API-Key: YOUR_SECRET_VALUE" "http://localhost:3000/api/temperature?station=EGLC&unit=C"
  curl -H "Authorization: Bearer YOUR_SECRET_VALUE" "http://localhost:3000/api/temperature?city=New%20York&unit=F"

Production:

  curl -H "X-API-Key: YOUR_SECRET_VALUE" "https://YOUR_DOMAIN/api/temperature?city=London&unit=C"
  curl -H "X-API-Key: YOUR_SECRET_VALUE" "https://YOUR_DOMAIN/api/temperature?station=KLGA&unit=F"

JavaScript fetch example:

  const res = await fetch("https://YOUR_DOMAIN/api/temperature?city=London&unit=C", {
    headers: {
      "X-API-Key": process.env.API_SECRET
    }
  });
  const data = await res.json();

Fields To Use In A Bot
----------------------

bestModel.maxTemperature.value
  Maximum temperature predicted by the best single model.

bestModel.accuracy.maeC
  Mean absolute temperature error in Celsius. Lower is better.

bestAverageModel.maxTemperature.value
  Maximum temperature predicted by the best averaged model combination.

bestAverageModel.accuracy.maeC
  Mean absolute temperature error for the averaged model. Lower is better.

averageImprovesBestModel
  true when the averaged model is more accurate than the best single model.


Security Notes
--------------

The temperature API requires an API key. Set the secret in your deployment
environment as:

  API_SECRET=YOUR_SECRET_VALUE

The bot must send the same value in one of these headers:

  X-API-Key: YOUR_SECRET_VALUE

or:

  Authorization: Bearer YOUR_SECRET_VALUE

If API_SECRET is not configured, the endpoint returns:

  500 API_SECRET is not configured

If the key is missing or incorrect, the endpoint returns:

  401 Unauthorized

Keep these rules:

1. A public GitHub repository is fine for this code, but never commit private API
   keys, bot tokens, passwords, cookies, or deployment secrets.
2. Store API_SECRET in Vercel environment variables, not in GitHub.
3. This endpoint calls external weather services. Heavy traffic could slow
   the site down or hit upstream rate limits.
4. If the key is ever exposed, rotate it by changing API_SECRET in Vercel and in
   the bot.
5. If traffic grows, also add rate limiting at the hosting or proxy layer.

Recommended setup for a private bot:

  - Add API_SECRET in Vercel environment variables.
  - Configure the bot to send X-API-Key with every request.
  - Reject API requests when the header is missing or incorrect.
  - Keep the GitHub repository public only if it contains no secrets.


Bot Weather API
===============

Endpoints
---------

GET /api/bot/weather

Use this endpoint from a bot to get current observations, a selected forecast,
and model accuracy data for one city.

POST /api/bot/weather/batch

Use this endpoint to request the same bot-friendly weather response for multiple
cities in one call.

These endpoints do not require API_SECRET.


Single-City Query Parameters
----------------------------

city
  Required unless station is enough to resolve the location.
  City name or city id for any city configured on the site.
  Examples: London, london, Amsterdam, amsterdam, Beijing, beijing

station
  Optional fallback or override METAR station code.
  Examples: EGLC, EHAM, ZBAA

date
  Required. Local forecast date in YYYY-MM-DD format.
  Example: 2026-05-13


Supported Site Cities
---------------------

The bot weather API uses the same city list as the site. The examples above are
not exhaustive. Any city shown in the site city selector can be requested by its
city name, city id, or METAR station code.


Single-City Examples
--------------------

Local development:

  curl "http://localhost:3000/api/bot/weather?city=London&date=2026-05-13"
  curl "http://localhost:3000/api/bot/weather?city=London&station=EGLC&date=2026-05-13"

Production:

  curl "https://YOUR_DOMAIN/api/bot/weather?city=London&date=2026-05-13"
  curl "https://YOUR_DOMAIN/api/bot/weather?city=Beijing&station=ZBAA&date=2026-05-13"


Batch Request
-------------

POST /api/bot/weather/batch

Request by city names:

{
  "date": "2026-05-13",
  "cities": ["London", "Amsterdam", "Beijing"]
}

Request by city ids:

{
  "date": "2026-05-13",
  "city_ids": ["london", "amsterdam", "beijing"]
}

Local development:

  curl -X POST "http://localhost:3000/api/bot/weather/batch" \
    -H "Content-Type: application/json" \
    -d "{\"date\":\"2026-05-13\",\"cities\":[\"London\",\"Amsterdam\",\"Beijing\"]}"

Production:

  curl -X POST "https://YOUR_DOMAIN/api/bot/weather/batch" \
    -H "Content-Type: application/json" \
    -d "{\"date\":\"2026-05-13\",\"city_ids\":[\"london\",\"amsterdam\",\"beijing\"]}"

Model Selection
---------------

For each city, the bot endpoint:

1. Gets same-date METAR observations from AviationWeather.
2. Searches forecast model candidates from Open-Meteo.
3. Scores the best single model against observations.
4. Scores averaged model combinations.
5. Selects whichever has the lower score.
6. Returns forecast data from the selected single model or averaged model set.

Lower mae_c, rmse_c, and score values are better.


Bot Fields To Use
-----------------

observations.latest_temp_c
  Latest observed temperature in Celsius.

observations.current_high_c
  Highest observed temperature so far on the requested local date.

forecast.day_max_c
  Forecast maximum temperature for the requested local date.

forecast.forecast_30min
  30-minute forecast points from now until one hour after the forecast day peak.
  That means the response includes the peak point plus two more half-hour
  snapshots after the peak. Half-hour points are interpolated between Open-Meteo
  hourly values.

forecast.next_30m_max_c, forecast.next_60m_max_c, forecast.next_90m_max_c,
forecast.next_120m_max_c
  Rolling maximum temperatures from the returned 30-minute forecast points.

best_model.type
  "single" when one model won, or "average" when an averaged model combination
  won.

data_quality.status
  "ok", "warning", or "peak_over". If status is "peak_over", the forecast peak
  has already passed for the requested local date and forecast_30min is empty.

errors
  Batch-only per-item failures. Successful city results still appear in items.
